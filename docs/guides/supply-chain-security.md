# Supply Chain Security

All container images and Helm charts are built with supply chain security controls in the CI/CD pipeline.

## Image Signing

All production container images (`openvox-operator`, `openvox-server`, `openvox-db`) are signed with [cosign](https://docs.sigstore.dev/cosign/) keyless signing using GitHub Actions OIDC.

### Verify Image Signatures

```bash
cosign verify ghcr.io/slauger/openvox-operator:latest \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp 'github\.com/slauger/openvox-operator'
```

### Verify Helm Chart Signatures

Helm charts pushed to `ghcr.io/slauger/charts/` are also signed:

```bash
cosign verify ghcr.io/slauger/charts/openvox-operator:0.9.0 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp 'github\.com/slauger/openvox-operator'
```

## Attestations

Each image includes:

- **SLSA Provenance** - Build provenance in [SLSA](https://slsa.dev/) format, generated by `docker/build-push-action` with `provenance: true`
- **SBOM** - Software Bill of Materials in SPDX format, generated with `sbom: true`

Both are attached as OCI referrers and can be inspected with cosign:

```bash
# List attestations
cosign tree ghcr.io/slauger/openvox-operator:latest

# Verify SBOM
cosign verify-attestation ghcr.io/slauger/openvox-operator:latest \
  --type spdxjson \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp 'github\.com/slauger/openvox-operator'
```

## Conforma Policy Validation

The release pipeline validates all production images with [Conforma](https://github.com/conforma) (`ec` CLI) against a set of supply chain policies.

### Policy Configuration

The policy is defined in `.conforma/policy.yaml` and includes:

- **`@minimal` collection** - base image registries, SBOM, SLSA provenance, attestation types
- **`@github` collection** - GitHub Actions OIDC certificate validation

### Validated Policies

| Policy | Description |
|--------|-------------|
| `base_image_registries` | Images must be built from approved registries (`registry.access.redhat.com/`, `registry.redhat.io/`) |
| `builtin.image.signature_check` | Images must have valid cosign signatures |
| `builtin.attestation.signature_check` | Attestations must be signed |
| `sbom_spdx` | Valid SPDX SBOM must be attached |
| `slsa_provenance_available` | SLSA provenance attestation must be present |
| `github_certificate` | Fulcio certificate must match the expected GitHub Actions workflow |

### Running Locally

Install the `ec` CLI and validate an image:

```bash
# Install ec CLI
curl -sSL https://github.com/conforma/cli/releases/download/v0.9.37/ec_$(uname -s | tr '[:upper:]' '[:lower:]')_$(uname -m) \
  -o /usr/local/bin/ec && chmod +x /usr/local/bin/ec

# Validate
ec validate image \
  --image ghcr.io/slauger/openvox-operator:latest \
  --policy .conforma/policy.yaml \
  --certificate-identity-regexp "https://github.com/slauger/openvox-operator/" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  --show-successes \
  --output yaml
```

## Base Images

All production images use Red Hat UBI9 base images:

| Image | Base |
|-------|------|
| `openvox-operator` | `registry.access.redhat.com/ubi9/ubi-minimal` |
| `openvox-server` | `registry.access.redhat.com/ubi9/ubi` |
| `openvox-db` | `registry.access.redhat.com/ubi9/ubi` |

Base image versions are tracked and auto-updated by Renovate.

## Container Security

All production containers run with:

- Non-root user (`USER 1001:0`)
- Read-only root filesystem (default since v0.10.0)
- No privilege escalation (`allowPrivilegeEscalation: false`)
- All capabilities dropped (`drop: ["ALL"]`)
- OpenShift random-UID compatible (`group=root(0)`)
