# Supply Chain Security

All container images and Helm charts are built with supply chain security controls in the CI/CD pipeline.

## Image Signing

All production container images (`openvox-operator`, `openvox-server`, `openvox-db`) are signed with [cosign](https://docs.sigstore.dev/cosign/) keyless signing using GitHub Actions OIDC.

### Verify Image Signatures

```bash
cosign verify ghcr.io/slauger/openvox-operator:latest \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp 'github\.com/slauger/openvox-operator'
```

### Verify Helm Chart Signatures

Helm charts pushed to `ghcr.io/slauger/charts/` are also signed:

```bash
cosign verify ghcr.io/slauger/charts/openvox-operator:0.9.0 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp 'github\.com/slauger/openvox-operator'
```

## Attestations

Each image includes:

- **SLSA Provenance (per-platform)** - Build provenance in [SLSA](https://slsa.dev/) format, generated by `docker/build-push-action` with `provenance: true`
- **SBOM (per-platform, SPDX)** - Software Bill of Materials generated by BuildKit with `sbom: true`, stored next to the provenance in the image index (unsigned)
- **SBOM (per-platform, CycloneDX)** - generated with [syft](https://github.com/anchore/syft) from the pushed image and attached as a signed cosign attestation, e.g. for [Dependency-Track](https://dependencytrack.org/)
- **Build Provenance (manifest index)** - GitHub-native build provenance attestation via `actions/attest-build-provenance`, attached to the multi-arch manifest index

The signed attestations are attached as OCI referrers and can be inspected with cosign. SBOMs describe a single platform image, so verify them against the platform digest rather than the multi-arch tag:

```bash
# List attestations
cosign tree ghcr.io/slauger/openvox-operator:latest

# Verify and extract the CycloneDX SBOM of the linux/amd64 image
DIGEST=$(crane digest --platform linux/amd64 ghcr.io/slauger/openvox-operator:latest)
cosign verify-attestation "ghcr.io/slauger/openvox-operator@${DIGEST}" \
  --type cyclonedx \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp 'github\.com/slauger/openvox-operator' \
  | jq -r '.payload' | base64 -d | jq '.predicate' > sbom.cdx.json

# Read the BuildKit SPDX SBOM
docker buildx imagetools inspect ghcr.io/slauger/openvox-operator:latest \
  --format '{{ json (index .SBOM "linux/amd64").SPDX }}'
```

### SBOMs as Release Assets

Every [GitHub release](https://github.com/slauger/openvox-operator/releases) also carries the SBOMs of all images it ships, one file per image, platform and format:

```text
openvox-operator-<version>-linux-amd64.cdx.json    # CycloneDX
openvox-operator-<version>-linux-amd64.spdx.json   # SPDX
openvox-server-9-<version>-linux-arm64.cdx.json
...
```

### SBOM Coverage

The `openvox-server` image ships JRuby's default gems (`net-imap`, `rexml`, `uri`, ...) inside `puppet-server-release.jar`, where SBOM generators do not look. The image build copies their gemspecs to `/opt/puppetlabs/server/apps/puppetserver/jruby-stdlib/specifications`, so syft, Trivy and other scanners report them as gem packages.

## Conforma Policy Validation

The release pipeline validates all production images with [Conforma](https://github.com/conforma) (`ec` CLI) against a set of supply chain policies.

### Policy Configuration

The policy is defined in `.conforma/policy.yaml` and includes:

- **`@github` collection** - GitHub Actions OIDC certificate validation, base image registries, signatures, and attestations

### Running Locally

Install the `ec` CLI (see the [Conforma releases](https://github.com/conforma/cli/releases) for the latest version) and validate an image:

```bash
# Install ec CLI (check releases page for latest version)
EC_VERSION="$(curl -s https://api.github.com/repos/conforma/cli/releases/latest | grep tag_name | cut -d'"' -f4)"
curl -sSL "https://github.com/conforma/cli/releases/download/${EC_VERSION}/ec_$(uname -s | tr '[:upper:]' '[:lower:]')_$(uname -m)" \
  -o /usr/local/bin/ec && chmod +x /usr/local/bin/ec

# Validate
ec validate image \
  --image ghcr.io/slauger/openvox-operator:latest \
  --policy .conforma/policy.yaml \
  --certificate-identity-regexp "https://github.com/slauger/openvox-operator/" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  --strict=false \
  --show-successes \
  --output yaml
```

Base image versions are tracked and auto-updated by Renovate.

## Container Security

All production containers run with:

- Non-root user (`USER 1001:0`)
- Read-only root filesystem (CRD default: `true`, configurable via `config.readOnlyRootFilesystem`)
- No privilege escalation (`allowPrivilegeEscalation: false`)
- All capabilities dropped (`drop: ["ALL"]`)
- OpenShift random-UID compatible (`group=root(0)`)
